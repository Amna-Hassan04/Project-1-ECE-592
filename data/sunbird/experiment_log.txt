CAPACITY EXPERIMENT
============================================================

Method:
Randomized dependent pointer chasing.
1,000,000 dependent loads per measurement.
Pointer cycle generated with fixed seed 12345.
Memory allocated with 64-byte alignment.
Timing uses RDTSC/RDTSCP with LFENCE serialization.
CPU affinity fixed to CPU 3.

Wide sweep:

============================================================
LINE SIZE EXPERIMENT
============================================================

Final method:
64-byte-aligned base address.
Two loads made dependent.
Both relevant cache lines flushed before each trial.
10,000 individual timing samples per offset.
Timing uses RDTSC/RDTSCP with LFENCE serialization.
CPU affinity fixed to CPU 3.

Raw distributions:
data/sunbird/line_dep_32_samples.txt
data/sunbird/line_dep_64_samples.txt

32-byte offset:
n = 10000
median = 252 timer units
mean = 231 timer units
p90 = 240 timer units
p99 = 1020 timer units
min = 220
max = 1238

64-byte offset:
n = 10000
median = 436 timer units
mean = 415 timer units
p90 = 425 timer units
p99 = 969 timer units
min = 405
max = 10630

Interpretation:
32-byte offset remains within the same inferred cache line,
allowing the dependent second load to benefit from the first load.
64-byte offset moves to a different cache line and produces
substantially higher dependent-load latency.

Timing-only inference:
Cache line size is strongly supported as approximately 64 bytes.

Earlier line-size benchmark versions were exploratory and should
NOT be used as final evidence because they changed working-set size
with spacing or allowed independent loads to overlap.
